# read: a page as Markdown

> A page's main content as Markdown: GET https://read.web.pkgforge.dev/<url> answers with the origin's own Markdown, else this service's extraction of its HTML, else a provider's rewrite, each named in provenance.

Host: `read.web.pkgforge.dev`. State: built.

Version: `0c6c90bbd663`, openapi.json's `info.version`, the first 12 hex digits of the SHA-256 of the four root documents (llms.txt, llms-full.txt, openapi.json, SKILL.md, in that order, joined by a newline), each rendered with an empty version; it changes whenever anything a caller reads in them changes.

Cost: free to every caller; no key, no account and no quota (never gated). The one exception is the operator's: a service can be switched off (503, reason `disabled`), and a spend breaker can cap each caller IP at 100 requests per 60 s for at most 12 hours (429, reason `rate-limited`).

CORS: every answer carries `access-control-allow-origin: *` and exposes the provenance headers; OPTIONS on a listed path is the preflight (204), and it allows every request header the browser names; no credentials.

Every service and its live status: https://web.pkgforge.dev/

## When to use

- the readable content of a web page as Markdown for a model: `GET /<url>` or `GET /?url=`
- a page that is rendered by JavaScript or behind a bot challenge: the read moves to a provider, or pin one with `__provider=<id>` on the path form (`/https://host/path?__provider=firecrawl`) or `provider=<id>` on `/?url=`
- a document that is not HTML (PDF, Word, Excel, OpenDocument, CSV, XML) as Markdown: the same `GET /<url>`; an image too with `__convert-images=1`
- not for the origin's bytes, status or headers: use fetch.web.pkgforge.dev
- not for search results: use search.web.pkgforge.dev

## Shared parameters

Two or more routes take each of these, as written here; each route names the ones it takes.

| parameter | in | required | schema | meaning |
| --- | --- | --- | --- | --- |
| `__mode` | query | no | `{"type":"string","enum":["markdown","text","clean"]}` | markdown (default); text: plain text of the selected content; clean: the extractor's Markdown tidied by Workers AI's llama-3.2-3b-instruct, kept only when it holds no sentence, link target, URL or code the extraction does not and was not stopped at its token budget (`x-reader-clean`), which spends Neurons. raw is a 400 naming fetch.web.pkgforge.dev |
| `__format` | query | no | `{"type":"string","enum":["markdown","json"]}` | markdown (default): YAML front matter, then the Markdown (the origin's own Markdown has none: it is byte for byte); json: one `application/json` object with the content and its facts, its keys snake_case (the 200 response states them) |
| `__provider` | query | no | `{"type":"string","pattern":"^[a-z0-9][a-z0-9-]{0,63}$"}` | a provider id, the pin on the path form (`/https://host/path?__provider=firecrawl`): the origin is not dialled, only that provider reads the page, and its refusal is the answer. On `/?url=` the key `provider=` does the same; on the path form a bare `provider=` is the target's own key, is sent to the origin, and `x-reader-hint` says so |
| `__links` | query | no | `{"type":"string","enum":["inline","referenced"]}` | inline (default) or referenced: link URLs listed at the end |
| `__images` | query | no | `{"type":"string","enum":["alt","keep","none"]}` | alt (default): an image is its alt text; keep: a Markdown image; none: dropped |
| `__max-bytes` | query | no | `{"type":"integer","minimum":4096,"maximum":10000000}` | the byte cap on the origin body, default 5000000 for a page and 10000000 for a document target (a declared document type, or an opaque type on a URL whose extension names one), clamped to 4096 to 10000000 |
| `__convert-images` | query | no | `{"type":"string","enum":["0","1"]}` | 1: an image target, and an image inside a converted PDF or Word file, is described by Workers AI, which spends Neurons; 0 (default): an image target is a 415 `not-html:image` and embedded images are left out |
| `__providers` | query | no | `{"type":"string","enum":["any","none"]}` | any (default); none: no third-party provider is asked, the origin and this service's extractor only (a document's conversion and a `__mode=clean` cleanup still run on Workers AI); every answer says `x-reader-providers: none`, and a page only a provider could read is refused with the origin's 4xx or 5xx when it sent one, e.g. a bot challenge behind a 403 is a 403 `challenge`. Not with `provider=` (a 400) |
| `__timeout-ms` | query | no | `{"type":"integer","minimum":1000,"maximum":25000}` | the read's own deadline in ms, 1000 to 25000 (default 25000); it lowers the deadline, never raises it. Past it the answer is a 504 `deadline` with `timeout_ms`. A value outside the range is a 400 |
| `__pages` | query | no | `{"type":"string","pattern":"^[0-9]{1,6}(-[0-9]{1,6})?$"}` | a PDF's pages, `7` or `51-100`, at most 60: read by unpdf alone, under a 20000000-byte cap, no conversion or provider (`x-reader-pages`, `pages_from`, `pages_to`); a range it cannot read is a `pages:<reason>` refusal, and on any other answer `x-reader-ignored` lists `pages` |
| `__max-words` | query | no | `{"type":"integer","minimum":1}` | the most words of content, cut at a block boundary, a code fence closed: `x-reader-truncated: words=<kept>/<total>`, `truncated: true` and `words_total` |

## Routes

### GET /healthz

service state and the running Worker version.

JSON `{ok, service, version: {id, tag, at}, built, entry?, d1: {ok, ms, error?}, keys?: {state, ms}, gate?}`, always `no-store`. `version.id` is the Worker version that answered; `d1` is a `SELECT 1` on the service's D1 database, bounded at 1 s, and a failed one answers 503 with `ok: false`. `keys`, on a service that calls providers, says whether it could open one sealed key of the store with its own secret (`ok`, `failed`, `secret-unset`, `no-key`, `timeout`), never a value. `gate` says whether the operator or a spend breaker switched the service off; an off service still answers 200 here. A 200 says the Worker and its database answer, not that every route does.

| status | content type | meaning |
| --- | --- | --- |
| 200 | `application/json` | up |
| 503 | `application/json` | down: the same `application/json` body as the 200 with `ok: false`, not a problem; the D1 database did not answer `SELECT 1` within 1 s (`d1.error`: `failed`, `timeout`, `unbound`) |

state and version:

```bash
curl -qfsS https://read.web.pkgforge.dev/healthz
```

### GET /{target}

a page as Markdown, path form.

`/https://host/path?q` (path-scheme) or `/host/path?q` (path-bare-host, https). `/https:/host/path` (one slash) is read as `https://host/path`. The query is the target's, byte for byte, minus the `__` controls listed below; any other `__` key (an origin's own `__token__`, or a mistyped `__fromat`) is the target's, is sent to the origin, and is named in `x-reader-forwarded`. A target sent as one percent-encoded segment (`/https%3A%2F%2Fhost%2Fpath`, as an OpenAPI client encodes `{target}`) is decoded once. On this form a provider is pinned with `__provider=<id>` in the query, `/https://example.com/?__provider=tinyfish`; a bare `provider=` is the target's own key, sent to the origin and named in `x-reader-hint`. Three sources, in order, each named in `x-reader-source`: (1) the origin, dialled through cf-fetch with `Accept: text/markdown` first, so a Cloudflare zone with Markdown for Agents answers with its own Markdown (a resolver that redirects by Accept, doi.org and dx.doi.org, is sent `Accept: text/html, application/xhtml+xml;q=0.9, */*;q=0.1` instead, and any other origin is asked again once with it when the Markdown-first answer is a 406 or, behind a response that varied on Accept, neither HTML nor Markdown; `x-reader-origin-accept` says which; the origin's Markdown full of raw HTML is asked for once more with HTML first and extracted, `x-reader-fallback: origin-markdown:raw-html`); (2) this service's extractor over the origin's HTML, bounded at `__max-bytes`, 100000 elements and 512 levels of nesting; (3) one provider chosen by tier, mode and health over providers > accounts > keys (TinyFish, Exa, Tavily, Context.dev, ZenRows, Firecrawl), whose body is its rewrite of the page, or a browser provider whose rendered DOM this service's extractor reads, `x-web-body: extracted`: Cloudflare Browser Run's /snapshot (`x-reader-source: extractor(cfbr)`; Cloudflare's own Markdown of the same load is answered instead, `x-reader-source: provider`, when the extraction keeps under 10% of its words or finds no page), Browserless after it, and last a scan of the exact URL that someone made with Cloudflare URL Scanner in the last 30 days (`x-reader-source: snapshot(cfscan)`, the scan's time in `x-web-snapshot-at`: a stored record, not a live read); a rendered DOM the extractor finds no page in moves to the next provider. The read moves to (3) only on a bot challenge, a page with no content, a page past the element or depth cap or this service's byte cap, a failed dial or body read (a Cloudflare zone's own 520-526 page among them), or an origin past 12000 ms (less under a lowered deadline, so a walk keeps 5000 ms), and says why in `x-reader-fallback`, and never past an origin's final status (any 4xx or 5xx but 403 and 429) unless the page is a bot challenge; a refused destination, a page past a byte cap the caller lowered, a target read neither as HTML, text nor a document, and an empty body are answered at once. A document target (PDF, Word, Excel, OpenDocument, Apple Numbers, CSV) is read under a cap of 10000000 bytes, or the `__max-bytes` the caller set; a PDF of at most 60 pages is read first by this service with unpdf (`x-reader-source: pdf(unpdf)`, `x-web-body: converted`), and any other document, or a PDF unpdf could not read (`x-reader-fallback: unpdf:<reason>`), is converted to Markdown by Workers AI's toMarkdown within 20000 ms, on the Cloudflare accounts' own Neurons first and this deployment's binding last, `x-reader-converter` naming which (`x-reader-source: tomarkdown`, `x-web-body: converted`, `x-reader-document` its media type); `__mode=text` asks the conversion for plain text. An image target is converted only with `__convert-images=1`, because a model describes it and that spends Neurons; so is an image inside a PDF or a Word file. Every redirect hop, at most 5, passes the destination guard before it is dialled. A capture URL of archive.web.pkgforge.dev (`/capture/<YYYYMMDDhhmmss>/<url>`, with no query or `?provider=wayback`) is read from the Wayback Machine's raw capture, `https://web.archive.org/web/<timestamp>id_/<url>`, and `x-reader-target-rewritten` names that URL; its relative links resolve against the captured URL, not web.archive.org; every other URL of web.pkgforge.dev is refused by the guard. Only user-agent (a scripted one replaced by a browser one), accept and accept-language reach the origin; never the caller's Cookie or Authorization. The whole read, a conversion and the providers included, is bounded at 25000 ms, or at the lower `__timeout-ms`; past it the answer is a 504 `deadline` with `retryable: true`, and no provider walk starts with under 5000 ms of it left; one provider attempt is bounded at 8000 ms, 20000 ms for a document target or a pinned provider. Under the default deadline a conversion runs to its own 20000 ms bound, and one that finishes after the deadline is stored, so the repeat is a hit; under a `__timeout-ms` the caller lowered, the conversion ends at that deadline too, and nothing is kept running for it. A conversion that fails goes to the providers that read documents (firecrawl) first, then any other, except after a PDF's leading pages were read here: those are the answer. `__providers=none` asks no third-party provider: the origin and the extractor only, `x-reader-providers: none` on every answer, and what only a provider could read refused with the origin's 4xx or 5xx when it sent one. A 200 of an unpinned GET is kept in a cache shared by every colo, 300 s for the origin's Markdown, the extractor's answer or a `low-confidence:*` answer and 3600 s for any other that cost a provider call or Workers AI Neurons, and an identical read (the same target, the same capture URL for an archive capture, and the same controls, and the same user-agent and accept-language as the origin is sent) inside that time is the stored answer with its own provenance, `x-web-cache: hit` and `x-web-snapshot-at`, and no `x-web-egress` because nothing was dialled, while its provider is still enabled. A HEAD that misses is read as a GET and stored. A refusal of no content (`no-content`), a block page (`challenge`), a sign-in wall (`login-wall`), a document the conversion refused (`tomarkdown:error`), a document the conversion found empty (`tomarkdown:empty`), a provider's per-URL miss (`provider-miss:*`) is stored 60 s, so a retry inside it pays for no walk; one that stands after the providers were asked is stored only when every provider asked refused the page, never when one was held, none could be asked, the walk stopped, or an attempt failed. A `__mode=clean` answer whose cleanup was skipped for `timeout`, `allocation`, `error`, `unbound` is not stored, because another try may pass; every other is. A read pinned with `provider=` is never served from it nor stored. Every refusal is an RFC 9457 problem (an origin's 4xx or 5xx page answered with its Markdown is not a refusal) with `reason`, and `x-reader-refused` names the reason; a refusal of a parsed read also carries `target`, and a malformed request (400 `bad-request`), a wrong method (405), an unknown route (404) or an internal error (500) does not. `__mode`, `__links` and `__images` apply to the extractor only, a rendered DOM included: an answer from the origin's Markdown or a provider's rewrite says `x-reader-mode: markdown` and lists each such control it did not apply in `x-reader-ignored`. `__mode=clean` is opt-in: the extractor's Markdown of the origin's HTML, up to 12000 characters, goes to Workers AI's llama-3.2-3b-instruct within 20000 ms, told to remove furniture and fix structure without adding text; its answer is kept only when its every sentence is the extraction's, its every link target, URL and piece of code the extraction's character for character, the model was not stopped at its token budget, and it keeps a quarter of the words or more (`x-reader-source: extractor+clean(llama-3.2-3b-instruct)`, `x-web-body: rewritten`); else the extraction is answered, `x-reader-clean: skipped(<reason>)` saying why. No other source is cleaned.

### GET /

a page as Markdown, ?url= form.

`/?url=<percent-encoded URL>` (query-url). On `/`, `url` and `provider` are controls, as are the `__` controls; any other key is appended to the target's query byte for byte. A GET or HEAD of `/` with no query names no target and is the index of this service: A browser (`Accept: text/html`) gets an HTML index: links to the four root documents and the status page, and each route with its parameters and examples; any other caller gets llms.txt as `text/plain`. The read itself (its sources, bounds, cache and refusals) is the path form's, stated once under `GET /{target}`.

| parameter | in | required | schema | meaning |
| --- | --- | --- | --- | --- |
| `url` | query | yes | `{"type":"string","format":"uri"}` | absolute http(s) URL, percent-encoded |
| `provider` | query | no | `{"type":"string","pattern":"^[a-z0-9][a-z0-9-]{0,63}$"}` | = __provider: only that provider reads the page; its refusal is the answer |

The shared answers 200, 400, 403, 405, 409, 413, 415, 422, 429, 502, 503, 504, 508, 530, each under Shared answers.

Relayed: as `GET /{target}`.

a target with `?` or `#`. The path form forwards the target's own query string (`?`) to the origin, and `#` never reaches a server: a client keeps the fragment. Send any URL that holds `?` or `#` percent-encoded in `?url=`:

```bash
curl -qfsS "https://read.web.pkgforge.dev/?url=https%3A%2F%2Fwww.cve.org%2FCVERecord%3Fid%3DCVE-2025-32711"
```

query-url:

```bash

```

as JSON:


a PDF, converted by Workers AI:

```bash
curl -qfsS -D - "https://read.web.pkgforge.dev/?url=https%3A%2F%2Farxiv.org%2Fpdf%2F2211.17192"
```

## Failure states

A path no route takes answers 404, reason `not-found`; a method a listed path does not take answers 405, reason `method-not-allowed`, with `Allow`; every non-2xx this service builds is an RFC 9457 problem whose `reason` is one of the values openapi.json publishes.

| status | when | what to do |
| --- | --- | --- |
| 400 | no target (`/` with a query but no `url`), an unparseable one, a scheme other than http(s); an unknown control value or a control given twice; `__mode=raw`; an unknown provider id; or the provider refused the URL as malformed | fix the request; do not retry it unchanged |
| 403 | `destination-refused`: the guard refused the target or a redirect hop (`hop`): loopback, private, link-local, metadata or reserved address; refused suffix; mail port; any host in web.pkgforge.dev but an archive capture URL, which is read from the Wayback Machine. Or, with `__providers=none`, the origin's 403 bot challenge (`challenge`; another 4xx or 5xx keeps its own status) | do not retry a destination-refused; nothing was dialled at that hop. For a challenge, drop `__providers=none` |
| 405 | a method other than GET or HEAD; OPTIONS is the CORS preflight (204) | use GET |
| 409 | the origin answered with a bot challenge or block page, whatever its status, or sent the read to its sign-in page (`login-wall`), and no provider read the page (body `providers`); a provider's sign-in page counts as none | do not retry unchanged (the same refusal is stored 60 s); pin a provider as `hint` shows: `__provider=<id>` on the path form, `provider=<id>` on `/?url=` |
| 413 | the page is past a `__max-bytes` the caller lowered, or past 5000000 bytes (by its `Content-Length` too, unread), 100000 elements or 512 levels of nesting and no provider read it in the deadline (`retryable: false`) | do not retry; raise `__max-bytes` for a lowered byte cap, or pin a provider: `__provider=<id>` on the path form, `provider=<id>` on `/?url=` |
| 415 | the target is JSON, binary, or another type read neither as HTML, text, a feed, XML nor a document the conversion takes, or is an image without `__convert-images=1` | add `__convert-images=1` for an image, or fetch it through fetch.web.pkgforge.dev |
| 422 | an empty or undecodable body, a page with no content that no provider read, or a provider's per-URL answer such as the origin's 404; behind an origin's final 4xx or 5xx the same refusal carries that status (an empty 404 is a 404 `empty-body`) | do not retry unchanged; a no-content refusal is stored 60 s, so a retry inside it is the same answer |
| 429 | a pinned provider is held by a rate limit or a spent allowance | retry after `Retry-After` seconds, or drop `provider` |
| 502 | the dial or body read failed, or the platform answered for an origin that is down, timed out, failed TLS (520-526) or blocked us (1020), and no provider read the page; the platform refused a destination no Worker may dial (1003); an unusable redirect; or every provider asked failed (body `errors[]`) | retry later |
| 502 | Workers AI could not convert a document (`reason: tomarkdown:error`, `retryable: false`) or did not within 20000 ms (`tomarkdown:timeout`, `retryable: true`), or every account was held with no binding to ask (`tomarkdown:held`, `retryable: true`), and no provider read it: the providers that read documents, then every other, were asked unless `__providers=none` (body `providers`) | retry only when `retryable` is true; else pin a provider that reads documents (`__provider=<id>` on the path form, `provider=<id>` on `/?url=`), or fetch the bytes through fetch.web.pkgforge.dev |
| 503 | a pinned provider cannot read: disabled, no read leg in this build, or no key | drop `provider` to let the chain choose |
| 504 | `deadline`: the origin did not answer within 12000 ms and no provider read the page, or the read passed its 25000 ms deadline or the lower `__timeout-ms` (`timeout_ms`, `retryable: true`), or under 5000 ms of it was left for the providers | retry after `Retry-After`, or with a larger `__timeout-ms`; under the default deadline a conversion that was still running is stored when it finishes, so the retry may be a hit |
| 508 | the origin redirected more than 5 times | do not retry |
| 530 | `dns-failure`: the target's name did not resolve (Cloudflare 1016, 1019) | do not retry: check the host name |
| 500 | a defect on this request; the error is logged | retry later |
| 503 | reason `disabled`: the operator, or a spend breaker, switched this service or every public service off; `scope` says which (`global` or `service`) and `since` since when. `/healthz` and the root documents still answer | wait `Retry-After` (60 s) and ask again; the state is read again every 5 s, and https://web.pkgforge.dev/status says when a service is off |
| 429 | reason `rate-limited`: a spend breaker caps each caller IP at 100 requests per 60 s on every public service, and this caller is past it | wait `Retry-After` and ask again; the cap lifts after at most 12 hours |

## Pipeline contract

Stable: paths and methods, `reason` values and provenance header names, held by `packages/docs/src/stable.json` (a removal or rename edits it). Each JSON answer's required fields:

- `GET /{target}`, `GET /`: `url`, `title`, `title_source`, `words`, `upstream_status`, `source`, `content_kind`, `extraction`, `final_url`, `fetched_at`, `content`

Retry, by what a client does:

- retry after `Retry-After`: 429 `held`; 504 `deadline`; 503 `disabled`, 429 `rate-limited` (any request route)
- retry with backoff: 502 `dial-failed`; 503 `deadline`, `budget`
- retry only when `retryable` is true: 502 `providers-failed`, `tomarkdown:*`; 422 `pages:*`; 413 `pages:*`
- no retry: fix the request: 400 `bad-request`, `provider-refused`, `unknown-provider`; 405 `method-not-allowed`
- no retry unchanged: 502 `bad-redirect`, `platform-refused`; 503 `none-configured`, `permanently-exhausted`; 403 `challenge`, `destination-refused`; 409 `challenge`, `login-wall`; 422 `decode-failed`, `empty-body`, `no-content`, `provider-miss:*`, `tomarkdown:empty`; 413 `too-deep`, `too-large`, `too-many-elements`; 415 `not-html:*`; 508 `too-many-redirects`; 530 `dns-failure`

Paging: no route pages; each answer is whole.
